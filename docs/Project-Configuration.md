# Конфигурация проекта GitHub

[Проект](https://github.com/users/Errroor/projects/1) связан с приватным репозиторием [LockingValve](https://github.com/Errroor/LockingValve). Приватность сохранена. База знаний размещается в каталоге docs вместо отдельной Wiki.

## Поля
Title, Assignees, Status, Приоритет (P0, P1, P2), Оценка сложности (число), Спринт (Iteration), Выпуск (MVP, Версия 1.0, Версия 2.0), Parent issue, Sub-issues progress. Системное поле Status сохраняет название. Отдельное поле Size шаблона не используется для оценки; итоговая оценка ведется только в числовом поле.

## Представления
Все спринты — доска по Status с боковым выбором поля Спринт и фильтром has:спринт. Бэклог продукта — таблица с приоритетом, выпуском, спринтом, оценкой и родителем. План разработки — Roadmap по выпускам с датами из итераций. На проверке — фильтр соответствующего статуса. Мои задачи — фильтр текущего пользователя. Дополнительная Иерархия показывает нативные родительские связи; это переработанное представление шаблона, а не отдельная доска следующего спринта.

## Итерации
13 двухнедельных спринтов с предварительными датами 26.10.2026–25.04.2027. Родительские элементы и 17 будущих историй не включаются в итерации. Состав и цели — в [плане](Sprint-Planning.md).

## Фактическая проверка
Созданы 79 реальных Issues и 71 нативная родительская связь. Все 79 строк Project проверены после перезагрузки: приоритеты, выпуски, оценки, спринты и статусы совпали с бэклогом. Переключение спринтов 3, 7 и 13 проверено по составу карточек.

Включены восемь правил: новые и обновленные открытые Issues репозитория добавляются в Project; подзадачи включаются в проект родителя; новый элемент получает Бэклог; закрытый Issue или Pull Request получает Выполнено; связь Pull Request с Issue переводит связанный элемент в работу; объединенный Pull Request получает Выполнено; статус Выполнено закрывает Issue; переоткрытый Issue или Pull Request возвращается в Бэклог. Условия и целевые статусы проверены в настройках каждого правила. Добавление задач и движение подготовительных карточек подтверждены реальными событиями. События связи и слияния PR, а также переоткрытия еще не испытывались: фиктивные изменения ради демонстрации не создавались.

## Ограничения
Не создаются фиктивные Pull Request ради проверки автоматики. Не включается автоматическое архивирование. Не утверждается проведение ревью, слияния или экспериментального расчета без результата. Владелец отдельно разрешил первый commit и push подготовленной базы знаний и шаблонов; последующие операции Git выполняются в пределах отдельного поручения.
